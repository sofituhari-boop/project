# Крестики-нолики: разбор и подготовка к защите

Это шпаргалка для вас, в сдаваемый код она не входит.

## 1. Игра за одну минуту (это и нужно рассказать первым)

> Состояние игры лежит в структуре `GameState`: поле, чей ход и статус.
> Она создаётся в `main` как локальная переменная, глобального состояния нет.
> В `main` крутится game loop: **считать ввод → обновить состояние → нарисовать**.
> Правила находятся в `logic`, они ничего не знают о Raylib.
> `layout` переводит клетки в пиксели и обратно, `graphic` рисует, `controller` читает мышь и клавиши.
> Собирается через Makefile.

## 2. Как выполнены требования

| Требование | Где |
|---|---|
| Графическая библиотека | Raylib: `graphic.cpp`, `controller.cpp`, `main.cpp` |
| Моделирование структурами | `logic.h`: `GameState`, `Board`, `Position`, `Player`, `GameStatus` |
| Процедурно: состояние передаётся в функции | `make_move(GameState& state, ...)`, `draw_game(const GameState& state, ...)` |
| Разделение на `.h` и `.cpp` | 4 модуля: `logic`, `layout`, `graphic`, `controller` |
| Система сборки | `Makefile` |
| Нет глобальных переменных | `state` и `layout` живут в `main`; `boardSize` — константа |
| Два игрока | `currentPlayer` меняется в конце `make_move` |
| Победа и ничья | `compute_status` в `logic.cpp` |
| Новая игра | клавиша R → `state = create_initial_game_state()` |

## 3. Карта файлов

```
main.cpp ──> controller ──> layout ──> logic
        └──> graphic ─────> layout ──> logic
```

Стрелка означает «использует». `logic` не использует никого, поэтому её можно тестировать без окна (`make test`).

## 5. Что происходит при одном клике

Окно открыто, ходит X, кликнули в точку `(280, 190)`.

1. `get_clicked_cell` видит нажатие и передаёт точку в `find_cell_at`.
2. `find_cell_at` перебирает 9 клеток. Шаг равен `160 + 10 = 170`.
   Клетка `{row 0, col 1}`: левый край `30 + 1 * 170 = 200`, верх `110`.
   280 лежит между 200 и 360, 190 — между 110 и 270. Попали, возвращаем `{0, 1}`.
3. `main` спрашивает `can_make_move`: игра идёт, клетка пуста → `true`.
4. `make_move` записывает X в `cells[0][1]`, пересчитывает статус, передаёт ход O.
5. `draw_game` рисует уже новое состояние.

Проговорите то же самое вслух для клика в промежуток `(195, 190)`: `find_cell_at` вернёт `nullopt`, и состояние не изменится.

## 6. Вопросы преподавателя и ответы

### Моделирование

**Почему клетка — `std::optional<Player>`, а не `enum { Empty, X, O }`?**
Клетка либо хранит игрока, либо пуста. С `Empty` внутри `Player` получилось бы, что `currentPlayer` тоже может быть `Empty`, а это бессмыслица. Сейчас такое состояние невозможно записать.

**Зачем хранить `status`, если его можно вычислить по полю?**
Да, можно каждый раз вызывать `compute_status`. Я считаю его один раз после хода и сохраняю, чтобы логика и графика просто читали готовое значение. Минус: поле и статус надо держать согласованными, поэтому поле меняет только `make_move`.

**Почему `status` — enum, а не два `bool`: `isDraw` и `hasWinner`?**
Два `bool` допускают невозможное «и ничья, и победа». У enum всегда ровно одно значение.

**Почему `enum class`, а не `enum`?**
Имена не попадают наружу (пишем `Player::X`), и нет неявного превращения в `int`.

**Зачем структура `Position`, если можно передать два числа?**
Строка и столбец логически связаны. И функция может вернуть их вместе: `std::optional<Position>`.

**Почему отдельно `Position` и `ScreenPosition`?**
Это разные вещи: клетка поля и пиксели. Разные типы не дают их перепутать.

**Почему `std::size_t`?**
Это тип индексов `std::array`. Отрицательных индексов не бывает, и нет лишних преобразований. Для Raylib нужен `int`, поэтому в `layout.cpp` стоит `static_cast<int>`.

### Ссылки, const, assert

**Почему `make_move` принимает `GameState&`, а `can_make_move` — `const GameState&`?**
Первая меняет состояние, вторая только читает. `const` запрещает случайное изменение, а `&` избавляет от копии.

**Что будет, если убрать `&` в `make_move`?**
Функция изменит копию. В `main` ничего не поменяется, и ходы не появятся на экране.

**Почему `Position` передаётся по значению?**
Это два числа, копия дешёвая.

**Почему ссылка, а не указатель?**
Ссылка не может быть `nullptr`, проверять нечего.

**Зачем `assert` в `make_move`, если `main` уже проверил?**
Это предусловие: вызвать `make_move` с занятой клеткой — ошибка программиста. Клик игрока по занятой клетке — обычная ситуация, её обрабатывает `if` с `can_make_move`.

**Что станет с `assert` при `NDEBUG`?**
Он исчезнет. Поэтому им нельзя проверять ввод пользователя.

**Что значит `*clickedCell`?**
Достаёт значение из `optional`. Если он пуст, это неопределённое поведение (UB), поэтому сначала `has_value()`.

**Почему в `if` порядок `clickedCell.has_value() && can_make_move(state, *clickedCell)`?**
`&&` вычисляется слева направо: если левая часть `false`, правая не выполняется. В обратном порядке мы разыменовали бы пустой `optional`.

**Как сравниваются `get_cell(board, b) != first`?**
Два `optional` равны, если оба пусты либо оба хранят равные значения.

### Логика

**Как определяется победа?**
8 линий: 3 строки, 3 столбца, 2 диагонали. `get_line_winner` проверяет одну линию, `find_winner` вызывает её для всех восьми.

**Зачем в `get_line_winner` проверка `first.has_value()`?**
Чтобы функция прямо говорила: пустая линия — не победа. Три пустые клетки ведь тоже равны между собой. (Честная тонкость: без неё вернулся бы `first`, то есть тот же `nullopt`. Проверка здесь для ясности.)

**Почему победа проверяется раньше ничьей?**
Девятый ход может и заполнить поле, и выиграть. Иначе показали бы ничью. На это есть тест `test_win_on_last_move_is_not_draw`.

**Почему после победы нельзя ходить?**
`can_make_move` возвращает `false`, если статус не `Playing`.

**`currentPlayer` меняется и после победного хода. Это ошибка?**
Нет: после конца игры это поле никто не использует, а победитель хранится в `status`.

### Файлы и сборка

**Что лежит в `.h`, а что в `.cpp`?**
В `.h` — структуры и объявления функций (интерфейс). В `.cpp` — определения (реализация).

**Зачем `#pragma once`?**
`logic.h` попадает в `main.cpp` несколько раз (напрямую и через `layout.h`). Без этого структуры определились бы повторно, и была бы ошибка компиляции.

**Что значит `static` у функции?**
Она видна только внутри своего `.cpp`. Это внутренние детали модуля.

**Что значит `inline constexpr`?**
`constexpr`: значение известно при компиляции и не меняется. `inline`: определение можно держать в заголовке, который включён в несколько `.cpp`.

**`boardSize` — это глобальная переменная?**
Это константа в глобальной области. Запрет касается изменяемого состояния. Нужна как размер `std::array`. В змейке так же объявлены константы направлений.

**Как происходит сборка?**
Каждый `.cpp` отдельно компилируется в `.o` (флаг `-c`), потом линкер соединяет все `.o` и Raylib в программу.

**Зачем Makefile?**
Он пересобирает только то, что изменилось. Слева от `:` цель, справа зависимости, ниже команда.

**Изменили `graphic.cpp`, что пересоберётся?**
Только `graphic.o` и сама программа. А если изменить `logic.h`, пересоберутся все `.o`.

**Что значат флаги?**
`-std=c++20` — стандарт; `-Wall -Wextra -Wconversion` — предупреждения; `-Werror` — предупреждение считается ошибкой; `-g` — для отладчика; `-I` — где искать `.h`; `-L` — где искать библиотеки; `-lraylib` — подключить `libraylib.a`.

**Зачем `.PHONY`?**
`run`, `test`, `clean` — не файлы, а команды. Без него файл с именем `clean` сломал бы команду.

### Raylib

**Что такое game loop?**
Цикл, где одна итерация — один кадр. `SetTargetFPS(60)` ограничивает до 60 кадров в секунду.

**Почему `IsMouseButtonPressed`, а не `IsMouseButtonDown`?**
`Pressed` истинно один кадр в момент нажатия, `Down` — всё время, пока кнопка зажата.

**Почему нет таймера и `GetFrameTime`, как в змейке?**
Змейка движется сама. Здесь состояние меняется только от клика.

**Что делают `BeginDrawing` / `EndDrawing`?**
Между ними рисуем кадр, `EndDrawing` показывает его на экране.

**Почему клетка рисуется до крестика?**
Нарисованное позже ложится сверху.

**Почему надписи на английском?**
В стандартном шрифте Raylib нет кириллицы.

**Почему столбец связан с `x`, а строка с `y`?**
Номер столбца растёт вправо, как `x`. Номер строки растёт вниз, как `y` на экране.

**4. Показать, сколько ходов сделано.**
<details><summary>Ответ</summary>

Посчитать занятые клетки, как в вашей `empty_count`. В `graphic.cpp`:

```cpp
static int count_moves(const Board& board)
{
    int count{ 0 };
    for (const auto& row : board.cells)
    {
        for (const auto& cell : row)
        {
            if (cell.has_value())
            {
                count++;
            }
        }
    }
    return count;
}
```

В `draw_game` после второго `DrawText`:

```cpp
DrawText(TextFormat("Moves: %d", count_moves(state.board)), 380, 65, 20, LIGHTGRAY);
```
</details>

**5. Счёт побед, который не сбрасывается по R.**
<details><summary>Ответ</summary>

Добавить в `GameState` поля `int xWins;` и `int oWins;`, в `create_initial_game_state` — `.xWins = 0, .oWins = 0`.
В конец `make_move`:

```cpp
if (state.status == GameStatus::XWon)
{
    state.xWins++;
}
if (state.status == GameStatus::OWon)
{
    state.oWins++;
}
```

Новая функция в `logic` (объявление — в `.h`):

```cpp
void start_new_round(GameState& state)
{
    state.board = {};
    state.currentPlayer = Player::X;
    state.status = GameStatus::Playing;
}
```

В `main` по R вызывать `start_new_round(state)`.
</details>

## 8. Как потренироваться писать с нуля

Создайте пустую папку рядом и пишите в таком порядке, не подглядывая дольше минуты:

1. `logic.h`: только структуры. Вопрос к себе: что нужно помнить об игре?
2. `create_initial_game_state`, `can_make_move`.
3. `make_move` без победы, только запись и смена игрока.
4. `get_line_winner` → `find_winner` → `is_board_full` → `compute_status`.
5. Тесты через `assert`.
6. `main` с пустым окном.
7. `layout`, потом рисование сетки, потом X и O.
8. Клик и клавиша R.

После каждого шага компилируйте.
